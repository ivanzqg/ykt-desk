# 播放器前台限制核对

核对日期：2026-11-03（北京时间）。课程班级：3203824；视频学习单元：6067660。

## 已观察到的原因

正常课程配置接口 `/c27/api/v1/platfrom/watermark` 当前返回 `anti_brushing: true`、`hide_video_speed: false`。本次只输出配置中的布尔值，没有输出身份水印字段。它说明倍速菜单允许使用，但课程开启了播放器的防挂机设置。

此前页面加载的公开脚本中，视频组件将这个配置传给播放器的 `is-anti-brushing` 属性。播放器 `winTriggerHidden` 注册了 `visibilitychange` 和窗口 `blur` 等事件；当后台播放不被允许时，事件会触发原播放器的暂停逻辑。

公开脚本的本地副本在 `.local/26547.abee85f7.js` 和 `.local/player-source.js`；它们来自此前已观察到的实际页面脚本URL。课程配置及观看日志的历史 REA 证据为 `ev_a54f120000c3052df6eae6ff9a59fa36fdd8d019d63763e951e1799cfd7e5a83`。2026-11-03 的配置复核使用工具自己的学生端 GET 请求，不是新的 REA Evidence。

## 本次实际验证

使用新建的临时标签测试，未改动用户原有队列。详细结果保存在 `.local/focus-verification.json`，由 `app/tests/verify-focus-live.mjs` 生成。

- 播放器倍速为 2×。
- 失焦后，页面的 `visibilityState` 仍为 `visible`，但 `document.hasFocus()` 为 `false`，视频暂停。
- 等待2.5秒后，播放器位置保持227.611899秒。
- 返回播放页后，恢复2×播放，位置推进到228.136987秒；标签ID不变，没有刷新或跳转到更早位置。
- 测试结束后视频暂停，测试标签关闭。

页面可见和窗口有焦点是两个不同条件。因此，把视频放到独立窗口或仅保持窗口可见，不足以保证操作其他窗口时继续播放。本次没有验证画中画、浏览器后台运行或自制日志上报能被计入课程完成度。

## 工具改动

开始视频前读取课程配置，状态同时检测页面可见性和焦点。受限制课程失焦时显示“等待播放页”，返回后从原位置继续。该等待状态支持暂停、停止和跳过；普通播放器暂停后的显式继续也保留原页面。

该次修复没有改写播放器配置、移除事件监听或发送自制观看心跳。当时只实现了前台状态处理。

验证：12项单元测试通过；真实浏览器失焦、保持暂停、恢复及停止测试通过。当前已运行的旧进程仍保留用户的待处理队列，代码改动在服务重启后生效。

## 后台并发版本更新

同日后续实现加入“后台播放”模式，为每个视频创建独立CDP会话，并使用Chrome的`Emulation.setFocusEmulationEnabled`。原播放器接收到的是浏览器仿真的焦点状态，因此不会因用户切换标签而停止实际媒体播放。

这是对浏览器环境的仿真，不证明用户同时注意多段视频，也不直接声明课程完成。媒体仍实际加载和解码，日志由原播放器生成；完成状态仍读取服务器的`completed`。课程明确禁用多视频播放时，启动检查拒绝同一课程的并发任务。

前台模式保留此前的焦点检测。并发模式支持1–4段，默认2段，各任务有独立的覆盖率和错误状态。
